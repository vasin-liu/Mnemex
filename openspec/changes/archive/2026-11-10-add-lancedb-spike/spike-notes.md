# ADR-001 退出标准观察

本文件只记录这次 spike 实际跑过的事。没跑的项写成阻塞，不写成通过。

1. 一致性（文件增、删、改名、分支切换）：自动化测试只覆盖了合成对齐键的写入、按键删除，以及重建时丢掉 SQLite 已不存在的键。没有对真实仓库做文件增删改名，也没有做分支切换。这项未通过，也未失败，是未跑。
2. Windows 打包 / Defender / 文件锁：本 change 没有 Tauri 打包，Defender 扫描没有单独做。本机 Windows 上补偿测试打开了本地 Lance 目录并完成读写，这只说明这次小规模读写没有被文件锁卡住，不能代替打包和 Defender。打包与 Defender 未跑。另外，`lance-encoding` 14.0.2 的构建脚本默认要系统里的 `protoc`；本机原先没有，编译前放到了用户本地目录并设置 `PROTOC`。这不是退出标准本身，但是 Windows 构建阻塞的实测原因。
3. 10 万级 chunk 增量重建的停顿：没有跑。不能写成可接受。
4. 单目录备份：Lance 数据集目录与 SQLite 文件由测试放在同一个父目录下（design D2），所以有一个可复制的目录形状。没有做复制后再打开的恢复演练。恢复未跑。
