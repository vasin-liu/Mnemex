# Design

## Context

见 proposal.md 的 Why。现状：`scan_text` 只返回章节列表；`write_sections` 只插入尚不存在的对象和 chunk。`chunks` 的删除触发器 `chunks_ad` 已经会把正文从 FTS5 摘掉，但没有调用方。`knowledge_events`、`chunks`、`knowledge_edge` 的外键指向 `knowledge_objects`，没有 `ON DELETE CASCADE`，`foreign_keys=ON`。事件规格原先不允许删除入口。对象标识来自「相对路径 + `/` + 标题路径」，不含扫描根；chunk 标识含内容哈希。路径以扫描时的 `/` 分隔符写入 `path` 列。

## Goals / Non-Goals

**Goals:**

- 对账规则放在 `mnemex-ingest`，落库放在 `mnemex-store`，CLI 只做组合。
- 读出当前文档章节和写入删除、更新、插入在同一个 SQLite 事务里。
- 扫描失败时不打开这个事务。

**Non-Goals:**

- 见 proposal 的范围。此处再钉死三条：不刷新 `created_at`；不追加「正文已更新」事件；不为向量库里可能残留的对齐键调用删除。

## Decisions

### D1 扫描结果带上路径分类

`scan_text` 改为返回扫描报告：解码成功的章节、本次见到的文本相对路径、其中非 UTF-8 的路径。文本相对路径包含空文件和非 UTF-8 文件，分隔符用 `/`。非 UTF-8 不产生章节，也不使扫描失败。备选：让调用方再走一遍目录自己分类——两次遍历可能不一致，否决。

### D2 纯函数算出差异，store 不依赖 ingest

`mnemex-ingest` 提供纯函数：输入是扫描报告和当前文档章节（对象标识、`/` 相对路径、内容哈希、chunk 标识），输出是要删除的对象标识、要更新的内容哈希、要删除的 chunk 标识，以及要新插入的章节。不读盘，不打开数据库。`mnemex-store` 不依赖 `mnemex-ingest`。备选：把规则写进 store——扫描语义会漏进存储层，否决。

判定顺序：

1. 相对路径属于非 UTF-8：该路径上的已有章节整段保留。
2. 相对路径不在本次见到的文本路径里：删除这些章节。
3. 路径还在，但对象标识不在本次章节里：删除该对象。空文件走这条，因为路径在、章节没有。
4. 对象标识还在：内容哈希不同则更新；chunk 标识不在本次结果里则删除；缺的 chunk 插入。

其他四种类型不进入这个函数的输入。store 列文档章节时按现有类型判别过滤。

### D3 删除顺序与事务

一个事务里先读出文档章节，再按 D2 的结果写入。删除一个对象的顺序：指向它的边（源或目标）、它的 chunk、它的事件行、最后对象行。chunk 的删除由已有 `chunks_ad` 同步全文索引。不新增迁移，`user_version` 保持 2。备选：给外键补 `ON DELETE CASCADE`——要升模式版本，而触发器已经够用，否决。备选：单独提供按序号删除事件的接口——和「留存对象的事件只追加」冲突，否决。

内容哈希只更新 `knowledge_objects.content_hash`。标题、标题路径、创建时间、生命周期不动。比较路径时读 `path` 列的原文，不经过 `PathBuf` 的显示形式，避免 Windows 把 `/` 印成 `\`。

新对象仍走现有插入，并追加一条规则来源的创建事件。已存在的对象不追加事件。新 chunk 仍走现有插入，待索引位保持默认。

### D4 CLI 只在扫描成功后调用

`index` 先 `scan_text`。失败则退出，不打开库上的对账事务。成功则在事务里列出文档章节、调用 D2、提交写入。仍然不调用 `LanceVectorStore::open`。参数和缺参行为不变。

## Risks / Trade-offs

- [向量库可能留着已删 chunk 的对齐键] → 本 change 不打开向量库。下次按 ADR-002 从 SQLite 当前行重建时丢掉这些键。
- [对象标识不含扫描根，两个目录里相同的相对路径和标题会撞成同一个对象] → 不加绑定列。规格里「换一个目录」用互不相同的相对路径（`a.md` / `b.md`）验收。相同路径的正文会就地换成后一次扫描的结果。
- [非 UTF-8 的旧正文会一直留到文件重新可解码或从磁盘消失] → 这是「跳过不等于删除」。文件重新成为合法 UTF-8 后，按 D2 第 4 步对账。
- [一处小改可能让后面的 chunk 标识都变，从而整段删除再插入] → 文本规模下可以接受。标识规则不改。
- [事件行会随文档章节一起消失] → 只发生在这条删除路径里。留存对象没有删除或改写事件的入口。

## Migration Plan

没有模式迁移，也没有已发布的用户库。已有的开发库下次索引时按 D2 删掉过期行。回滚是 revert 本 change；库文件不需要降版本。
