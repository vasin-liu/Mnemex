# ADR-002：双库一致性协议

## 状态

Accepted

## 背景

结构化事实与向量不在同一个库里，没有跨库事务。Phase 0 必须先定谁是真相、失败后怎样追平。

## 决策

- **SQLite 是 source of truth**。LanceDB 可以全量重建。
- 两边以 `chunk_id` + `content_hash` 对齐。
- 不做跨库事务。补偿流三段：**SQLite 提交 → LanceDB 追平 → 哈希校验**。
- 维度变更与换模型同级，走全量重嵌（见 ADR-003 的 MRL 政策），不在本协议里做原地改维。

## 备选方案

- 跨库两阶段提交：单机进程的崩溃窗口用补偿流覆盖，不引入分布式事务。
- 以向量库为真相：知识对象、FTS 与 edge 都不在向量库里。

## 后果

- `VectorStore` 必须能按对齐键删除，并支持全量重建。
- 一致性在文件增删改名与分支切换下的可执行性，是 ADR-001 Spike 的第一项退出标准。
