# 个人知识与代码管理系统 — 产品路线规划

> 定位：一款隐私优先的本地桌面应用，持续扫描、解析、总结、关联本地文档（Word/Excel/PDF/Markdown/TXT）与多语言代码（Java/Rust/Go/Python/TypeScript/Kotlin/SQL），并将结构化知识以 MCP 协议对外开放，作为 AI Agent 的可持续成长的共享记忆。

---

## 一、产品愿景

不做又一个"本地搜索工具"，而是做一个**会持续学习你、并能被 AI Agent 直接调用的第二大脑**。核心判断：

- 检索谁都能做，但"在你没想起来的时候替你想起来"才是记忆系统和搜索引擎的本质区别。
- 隐私优先不等于牺牲能力——默认本地小模型 + 可选云端增强 + 策略级强制隔离，三者可以共存。
- 系统的价值随时间复利增长：越用得久，历史决策、跨项目模式、个人风格画像积累得越多，Agent 借助这份记忆给出的建议就越贴近"你会怎么做"，而不是通用最佳实践。

---

## 二、总体架构（八层流水线）

```
1. 采集层        fs watch + 全量/增量扫描 + hash 指纹
2. 解析提取层    docx/xlsx/pdf/md + tree-sitter 代码 AST
3. 语义分块层    文档按章节，代码按符号/函数级切分
4. 向量化存储层  本地/云端 embedding（策略路由）+ LanceDB/sqlite-vec
5. 分层摘要层    chunk → 文件 → 模块 → 项目，增量再生成
6. 关联图谱层    调用/引用/共现关系，SQLite edge 表或 KuzuDB
7. MCP 共享记忆层 search / get_related / get_summary 等 tool
8. Tauri UI 层   扫描状态 / 检索面板 / 关联图可视化
```

### 隐私架构（贯穿全层的横切关注点）

- **默认本地推理**：文本 embedding 用 BGE-M3（中英混合场景友好），代码 embedding 单独用 jina-embeddings-v2-base-code 一类的代码专用模型，两套向量空间按 chunk 类型路由，避免单一模型精度打折。
- **本地摘要**：默认用 Qwen2.5-7B 量化版（GGUF，经 llama-cpp-rs 调用），满足日常摘要质量；复杂跨文件综合分析可按需切换云端 API。
- **Provider 抽象**：`EmbeddingProvider` / `SummaryProvider` trait 统一接口，Local/Cloud 实现可插拔，配置驱动切换。
- **策略级强制隔离**：按目录 / glob 规则声明"禁止出云"的路径，命中规则时即使全局开启云端能力也强制走本地，靠代码级硬约束而非用户自觉（类比此前在包治理中用 `animal-sniffer-maven-plugin` + Checkstyle `ImportControl` 做硬边界的思路）。

## 三、长期愿景：三大能力支柱

系统的长期竞争力不在检索准确率，而在以下三个随时间积累、越用越值钱的能力：

### 1. 时间维度（历史记忆）

- **事件溯源模型**：知识变更不是覆盖更新，而是不可变事件追加写入（`knowledge_events` 表），保留完整版本链，区分"状态查询"（走快照表，快）和"历史查询"（走事件表）。
- **自动决策日志**：绑定 git commit（message + diff + 涉及符号），自动沉淀"问题-诊断-方案"三元组，减少手写 ADR 的负担。
- **成本控制**：滚动存储策略，仅在语义变化超过阈值或关键节点保留完整 payload，其余只记 hash 与时间戳。

### 2. 主动关联（从"问答"到"提醒"）

- **实时触发**：监听当前活跃编辑文件（IDE 最近文件列表或 LSP proxy），增量计算 embedding，实时检索相似历史内容。
- **去重与冷却机制**：避免重复提示同一关联，按用户是否点开做隐性反馈，未采纳的提示类型逐渐降权。
- **非侵入呈现**：桌面端做成可展开的侧边角标，而非弹窗打断心流。
- **价值分层过滤**：语义相似不等于有价值，需要叠加"上下文类型"权重——调试记录/踩坑经验这类最易被遗忘、最具价值的记忆类型应优先加权提示。

### 3. 跨项目模式挖掘（个人技术风格画像）

- **显式模式库**（优先落地）：定期聚类不同项目中语义相近的决策记录，人工确认种子模式后，新场景可自动匹配相似模式并提示"这和你在 XX 项目处理过的情况类似"。
- **隐式风格画像**（长期演化）：统计命名习惯、架构决策倾向（如偏好全量同步优先于增量、偏好插件化扩展点）等模式，用于新项目的架构建议对齐个人风格，也可作为定期自我复盘的输出。

**演化依赖顺序**：时间维度 → 主动关联 → 模式挖掘。时间维度提供决策日志素材，主动关联建立相似度基础设施，模式挖掘依赖前两者沉淀的数据，因此这是合理的分阶段实现路径，而非三者并行铺开。

## 四、阶段路线图

### Phase 0 — 基础设施（MVP）
- fs watch + hash 指纹全量/增量扫描
- 多格式解析（docx/xlsx/pdf/md/txt）+ tree-sitter 多语言代码解析
- 语义分块（文档按章节，代码按符号级）
- 本地 embedding + 向量库落地（LanceDB 或 sqlite-vec 二选一验证）
- SQLite 结构化元数据（文件树、符号表、chunk 映射）

### Phase 1 — 检索与摘要闭环
- 混合检索（关键词 + 语义）
- 分层摘要（chunk → 文件 → 模块 → 项目），增量再摘要
- Provider 抽象落地：本地默认 + 云端可选切换
- 隐私策略层：目录级"禁止出云"硬约束

### Phase 2 — 共享记忆开放
- 封装本地 MCP Server，暴露核心 tool：
  - `search_semantic` / `search_symbol`
  - `get_related`
  - `get_summary`
  - `get_context_bundle`
- Tauri UI：扫描状态、检索面板、关联图可视化（延续 Drift 液态玻璃视觉语言）

### Phase 3 — 时间维度
- 事件溯源模型上线（`knowledge_events`）
- Git commit 绑定的自动决策日志生成
- 历史查询 MCP tool：`get_history_at`

### Phase 4 — 主动关联
- 活跃编辑文件监听 + 实时相似度提醒
- 去重/冷却/隐性反馈权重机制
- MCP tool：`get_active_context_alerts`

### Phase 5 — 跨项目模式挖掘
- 决策记录聚类 + 显式模式库（人工确认种子模式）
- 隐式风格画像统计（命名习惯、架构决策倾向）
- MCP tool：`get_pattern_matches`

### Phase 6（探索方向，非承诺路线）
- 反馈闭环：摘要/关联准确度打分，作为排序权重调整乃至未来 LoRA 微调的信号来源
- 多设备同步：轻量方案（文件级同步工具，如 Syncthing 类）先行，视需求再评估 CRDT 方案

## 五、技术选型速查

| 层级 | 候选方案 | 备注 |
|---|---|---|
| 文件监控 | Rust `notify` | 需配合定时全量兜底扫描 |
| 文档解析 | docx-rs / calamine / pdf-extract / lopdf | 扫描版 PDF 需接 OCR |
| 代码解析 | tree-sitter | 覆盖 Java/Rust/Go/Python/TS/Kotlin/SQL |
| 文本 embedding | BGE-M3 | 中英混合场景 |
| 代码 embedding | jina-embeddings-v2-base-code 等 | 与文本走独立向量空间 |
| 推理后端 | ort（ONNX Runtime） | 优先追求性能；candle 备选（纯 Rust 无 C 依赖） |
| 本地摘要模型 | Qwen2.5-7B-Instruct（GGUF 量化） | 经 llama-cpp-rs 调用 |
| 向量库 | LanceDB / sqlite-vec | 前者原生 Rust + hybrid search，后者运维最简单 |
| 图存储 | SQLite edge 表 + 递归 CTE / KuzuDB | 复杂度上升后再迁移嵌入式图库 |
| Agent 集成 | MCP Server | 供 Claude / Cursor 等任意 MCP 客户端挂载 |

## 六、风险与待验证问题

- **本地推理性能天花板**：7B 级模型在普通笔记本上的摘要延迟是否可接受，需要早期基准测试。
- **主动关联的噪音控制**：去重/冷却参数需要真实使用数据调优，避免功能上线即被关闭。
- **模式库的自动化边界**：显式模式库前期依赖人工确认种子，自动化聚类质量需要持续评估，避免"伪模式"污染画像。
- **多设备同步**：如果长期只用单机，可以完全跳过这块投入，按实际需求触发。
