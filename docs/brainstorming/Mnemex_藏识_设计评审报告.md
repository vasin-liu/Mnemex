# Mnemex / 藏识 全方位设计评审报告

## 1. 评审对象

本次评审基于以下设计文档：

-   《Mnemex藏识-产品与设计深化建议》
-   《藏识Mnemex-UI设计规范》
-   《个人知识与代码管理系统-产品路线规划》

整体目标：评估产品定位、架构设计、技术路线、UI体系、工程可落地性、长期演进风险，并给出优化建议。

------------------------------------------------------------------------

# 一、总体评价

## 综合评分：8.5 / 10

Mnemex 的整体方向具有较高创新价值，核心定位"代码 + 文档统一记忆层 + AI
Agent 可调用记忆基础设施"明显区别于传统 PKM 产品。

设计优势：

-   避开 Obsidian / Notion 的正面竞争。
-   把知识管理提升到 Agent Memory Infrastructure 层。
-   本地优先、隐私控制、事件溯源等方向符合长期趋势。
-   UI 设计具有品牌识别度。

主要风险：

1.  产品边界较大，容易陷入"AI IDE + PKM + Agent 平台"的复杂化。
2.  主动关联、模式挖掘等高级能力依赖长期数据积累。
3.  本地 AI 推理性能可能成为体验瓶颈。
4.  MCP 依赖需要进一步抽象，避免协议绑定。

------------------------------------------------------------------------

# 二、产品定位评审

## 优点

当前定位：

> 面向工程师/技术负责人的代码+文档统一记忆层。

这是正确方向。

相比通用知识管理：

-   代码具有天然结构。
-   Git 提供时间线。
-   文档存在决策上下文。
-   Agent 对工程知识需求明确。

建议继续强化：

"不是笔记软件，而是开发者长期技术记忆基础设施"。

------------------------------------------------------------------------

## 风险

目前覆盖范围：

-   文档管理
-   代码解析
-   向量搜索
-   图谱
-   Agent Memory
-   主动提醒
-   技术画像

容易导致 MVP 失控。

建议：

第一阶段只解决：

> "让 AI Agent 能可靠理解一个工程项目"

不要过早做个人画像。

------------------------------------------------------------------------

# 三、架构评审

## 当前架构优点

八层流水线设计合理：

采集 -\> 解析 -\> 分块 -\> embedding -\> 摘要 -\> 图谱 -\> MCP -\> UI

符合现代 RAG + Memory 架构。

------------------------------------------------------------------------

## 关键优化建议

## 1. 增加 Knowledge Object 层

当前：

文件 -\> chunk -\> embedding

建议：

文件 ↓ Knowledge Object ↓ Chunk ↓ Embedding

Knowledge Object 类型：

-   CodeSymbol
-   DesignDecision
-   BugRecord
-   DocumentSection
-   CommitEvent

原因：

Agent 不需要文件，而需要知识实体。

------------------------------------------------------------------------

## 2. 图谱不要过早引入图库

建议：

Phase 0-3：

SQLite:

knowledge_node knowledge_edge

即可。

不要提前引入 KuzuDB。

原因：

真正瓶颈不是存储，而是关系质量。

------------------------------------------------------------------------

## 3. 增加 Ranking Pipeline

当前重点偏向召回。

建议增加：

Query ↓ Keyword Search ↓ Vector Search ↓ Graph Expansion ↓ Reranker ↓
LLM Context Builder

否则容易出现：

"找到很多相关内容，但不是最有用内容"。

------------------------------------------------------------------------

# 四、Agent Memory 评审

## 优点

事件溯源设计非常正确。

knowledge_events 表可以成为核心资产。

------------------------------------------------------------------------

## 建议增加 Memory 生命周期

当前缺少：

记忆创建 ↓ 验证 ↓ 强化 ↓ 衰减 ↓ 归档

建议增加：

memory_score:

-   confidence
-   usage_count
-   last_used
-   freshness
-   contradiction_score

否则长期运行后知识库会污染。

------------------------------------------------------------------------

# 五、MCP 设计评审

## 当前问题

MCP 不应该成为核心业务层。

建议：

核心：

Memory Engine

↓

Adapter:

-   MCP Server
-   HTTP API
-   CLI
-   IDE Plugin

这样未来支持：

-   Cursor
-   Claude
-   Continue
-   自研 Agent

无需修改核心。

------------------------------------------------------------------------

# 六、技术选型评审

## Rust + Tauri

评价：

推荐。

优势：

-   Windows 桌面体验优秀。
-   文件扫描性能好。
-   本地模型调用方便。
-   单机部署简单。

------------------------------------------------------------------------

## SQLite

推荐继续使用。

建议增加：

-   WAL 模式
-   FTS5
-   sqlite-vec
-   JSON1

形成轻量本地知识数据库。

------------------------------------------------------------------------

## 本地模型

风险：

7B 模型对于普通用户机器压力较大。

建议：

分级：

L0: 规则摘要

L1: 小模型 embedding

L2: 本地 3B-7B

L3: 云端增强

------------------------------------------------------------------------

# 七、UI 设计评审

## 优点

UI 方向成熟：

-   Liquid Glass
-   Memory Core
-   本地优先可见
-   非侵入提醒

品牌识别度较强。

------------------------------------------------------------------------

## 改进建议

## 增加开发者工作流界面

当前偏知识管理。

建议增加：

### Project Memory View

展示：

项目结构：

-   技术栈
-   核心模块
-   最近决策
-   历史问题
-   Agent 建议

这是区别普通 PKM 的关键。

------------------------------------------------------------------------

# 八、路线规划评审

## 推荐调整

原路线：

Phase 0-6

建议：

## Phase 0

基础索引：

-   文件扫描
-   Git 分析
-   AST
-   SQLite

## Phase 1

工程知识库：

-   符号级检索
-   决策记录
-   项目摘要

## Phase 2

Agent Memory：

-   MCP
-   Context Bundle

## Phase 3

主动关联

## Phase 4

模式发现

原因：

代码场景比通用知识更容易形成闭环。

------------------------------------------------------------------------

# 九、关键风险清单

  风险           等级   建议
  -------------- ------ -----------------
  范围膨胀       高     收缩 MVP
  本地模型性能   高     多级 AI 策略
  检索质量       高     增加 rerank
  数据污染       中     Memory 生命周期
  MCP变化        中     协议解耦
  图谱价值不足   中     延迟图库

------------------------------------------------------------------------

# 十、最终建议

Mnemex 最值得投入的方向：

## 第一优先级

打造：

> AI Agent 的本地工程记忆系统

## 第二优先级

强化：

> Git + Code + Decision Memory

## 第三优先级

发展：

> 个人技术风格模型

不建议：

-   早期做通用笔记编辑器。
-   早期做多人协作。
-   早期做复杂知识图谱。

------------------------------------------------------------------------

# 最终结论

该项目具备成为"开发者 AI 第二大脑"的潜力。

当前设计完成度较高，但需要从：

"完整知识管理平台"

收敛为：

"工程师 AI Agent Memory Engine"。

如果控制范围，优先解决工程知识理解和 Agent
上下文供应问题，具备形成差异化产品的可能。
